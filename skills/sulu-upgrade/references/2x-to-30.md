# 2.6 → 3.0 rename tables

Distilled from `UPGRADE-3.x.md` (section `3.0.0`) in sulu/sulu. For anything not
listed here, consult that file's "Moved classes for 3.0", "Moved services for 3.0"
and "Removed deprecations for 3.0" sections directly.

## Bundles (`config/bundles.php`)

Remove:

```php
Sulu\Bundle\RouteBundle\SuluRouteBundle::class
Sulu\Bundle\SnippetBundle\SuluSnippetBundle::class
Sulu\Bundle\ArticleBundle\SuluArticleBundle::class
ONGR\ElasticsearchBundle\ONGRElasticsearchBundle::class
Sulu\Bundle\CustomUrlBundle\SuluCustomUrlBundle::class
```

Add:

```php
Sulu\Content\Infrastructure\Symfony\HttpKernel\SuluContentBundle::class => ['all' => true],
Sulu\Route\Infrastructure\Symfony\HttpKernel\SuluRouteBundle::class => ['all' => true],
Sulu\Messenger\Infrastructure\Symfony\HttpKernel\SuluMessengerBundle::class => ['all' => true],
Sulu\Article\Infrastructure\Symfony\HttpKernel\SuluArticleBundle::class => ['all' => true],
Sulu\Snippet\Infrastructure\Symfony\HttpKernel\SuluSnippetBundle::class => ['all' => true],
Sulu\Page\Infrastructure\Symfony\HttpKernel\SuluPageBundle::class => ['all' => true],
```

## Routes (`config/routes/sulu_admin.yaml`)

- Drop `sulu_core` (rest routing) and `sulu_custom_urls_api`.
- Bundle routing files moved and lost the `type: rest`:
  `@SuluSnippetBundle/config/routing_admin_api.yaml`,
  `@SuluRouteBundle/config/routing_admin_api.yaml` — and new entries for
  `@SuluPageBundle/config/routing_admin_api.yaml`,
  `@SuluArticleBundle/config/routing_admin_api.yaml`, all with prefix `/admin/api`.
- Compare against a fresh [skeleton 3.0](https://github.com/sulu/skeleton/tree/3.0)
  `config/routes/sulu_admin.yaml` — aligning with it wholesale is usually faster
  than patching.

## Template XML

| 2.6 | 3.0 |
| --- | --- |
| `<controller>Sulu\Bundle\WebsiteBundle\Controller\DefaultController::indexAction</controller>` | `<controller>Sulu\Content\UserInterface\Controller\Website\ContentController::indexAction</controller>` |
| `<property name="url" type="resource_locator">` | `<property name="url" type="route" mandatory="true">` |
| article: `<property name="routePath" type="route">` + `<tag name="sulu_article.article_route"/>` | `<property name="url" type="route" mandatory="true">` + `<tag name="sulu.rlp"/>` |
| route generation configured in yaml (`entity_class`) | `route_schema` param on the `route` property |
| article types in `sulu_article.types` (yaml) | `<group>blog</group>` element in the template XML; translation key `sulu_admin.template_group.<name>` |

Every routable template needs at least one property tagged `sulu.rlp.part` (usually
`title`) — route generation moved to the frontend and triggers on unfocus of tagged
properties. Custom website controllers now extend the new `ContentController`.

## Twig

| 2.6 | 3.0 |
| --- | --- |
| `sulu_content_load(uuid, ?props)` | `sulu_page_load(uuid, props, ?locale)` / `sulu_article_load(uuid, props, ?locale)` — split by resource, `props` now **mandatory**, format `{'output_key': 'resolver_path'}` |
| `sulu_snippet_load_by_area(area, ?webspace, ?locale)` | `sulu_snippet_load_by_area(areaKey, props, ?webspace, ?locale)` |
| `sulu_navigation_root_flat` / `_root_tree` / `sulu_navigation_flat` / `_tree` | same names with `sulu_page_` prefix |
| `sulu_breadcrumb` | `sulu_page_breadcrumb` |
| `sulu_navigation_is_active` | `sulu_page_navigation_is_active` |

## Configuration

Template paths moved from `sulu_core` to `sulu_admin`:

```yaml
# 2.6
sulu_core:
    content:
        structure:
            default_type: { snippet: 'my_key' }
            paths:
                my_dir: { path: '…', type: snippet }

# 3.0
sulu_admin:
    templates:
        snippet:
            default_type: 'my_key'
            directories:
                my_dir: '…'
```

Other notable changes:

- `massive/search-bundle` removed — search runs on CMS-IG SEAL
  (`config/packages/cmsig_seal.yaml` in the skeleton).
- Flysystem 3 for media storage — storage config changes if customized.
- ResourceLocator endpoint: `/admin/api/resourcelocators?action=generate` →
  `/admin/api/resource-locators`, expecting `resourceKey`/`resourceId` instead of
  `entityClass`/`entityId`.
- DoctrineMigrationsBundle is now the migration mechanism; `doctrine:schema:update`
  remains off-limits.

## Admin build (`assets/admin/package.json`)

Handled by `bin/console sulu:admin:update-build`; for manually maintained files the
JS packages moved from `vendor/sulu/sulu/src/Sulu/Bundle/<X>Bundle/Resources/js` to
`vendor/sulu/sulu/packages/<x>/assets/js` (page, snippet, route, search, custom-url).

## User/security data

The 3.0.0 section documents dedicated migrations for: user entity columns, entities
depending on `TimestampableInterface` (→ `DateTimeImmutable`), permission settings,
removed groups/user-groups, legacy user settings. Run the shipped doctrine
migrations rather than writing these by hand.
